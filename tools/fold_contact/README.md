# fold_contact · 腿关节转到哪儿会被零件顶住

零位标定想拿「缩着」当机械参考点（悬空手扶着摆直，一两度的误差就会摔），先得知道：缩着的时候每个关节是被什么顶住的、停在多少度。这个脚本用官方仿真模型算这件事。

**最后的做法**（调试台 [`tools/servo-web`](../servo-web/) 0.14.0 起的「官方折叠（头颈摆正）」基准）：腿按官方 FOLD 摆，膝折到踝刚贴上大腿舵机（下表第 2 行的接触点），髋 pitch 用直角尺摆垂直；髋 yaw / roll、踝、头颈摆正（0°），嘴闭上；15 颗一起标，零点照样是官方的 2048。

```bash
pip install mujoco python-fcl numpy
python fold_contact.py --mjcf <microduck_rl>/src/mjlab_microduck/robot/microduck/robot_walk.xml [--json 结果.json]
```

- MuJoCo 只算正运动学（每个零件在哪）。碰没碰上用 **fcl 按原始三角网格精确求交**：MuJoCo 自己的碰撞把网格当凸包，比实物「胖」，接触角会偏小
- 零位（腿伸直）时就穿插的 20 对几何体当作装配关系（舵机装在支架里、轴承装在座里），扫描时排除
- 扫描步长 0.25°，碰上以后二分到 0.05°

## 结果（官方 XL330 原版几何，2026-09-22，microduck_rl d424a0c）

模型约定的角度，下表写左腿。右腿的膝、踝数值相同、符号相反；**髋 pitch 不对称**（左右外壳不一样），两边都列了。

| 关节 · 条件 | 碰上的角度 | 谁顶住谁 |
|---|---|---|
| 膝往折叠方向，髋 0°、踝 0° | **±70.7°** | 脚掌碰髋 roll 支架 |
| 膝往折叠方向，髋 ±90°（官方 FOLD 的髋）、踝 0° | **±89.6°** | 踝碰大腿上的舵机 |
| 髋 pitch 往折叠方向，膝已折到底 | 左 **+126.0°**，右 **−122.9°** | 踝碰躯干外壳 |
| 踝，膝和髋都折到底之后 | 只剩 **+0.4 ～ −19.8°** 能动 | 一头碰外壳，一头碰大腿 |
| 颈 pitch 往官方 FOLD 的方向，腿折好 | **+66.6°**（头 pitch 0° 和 57° 一样） | 颈上的舵机碰躯干外壳 |

官方的三个姿势（`scene.xml` keyframe）：

| 姿势 | 零件会不会顶在一起 |
|---|---|
| STAND 站 | 不会 |
| SIT 坐 | 不会 |
| FOLD 折叠（髋、膝 ±90°） | **会**：踝顶进大腿舵机约 0.36°（官方膝 1.57 rad = 89.95°，接触在 89.59°）。FOLD 的膝几乎就是接触点；调试台发折叠时膝只折 88° |

FOLD 的颈 / 头 pitch 是 57°（1 rad），不是接触点：颈要转到 **66.6°** 才碰上零件，57° 那里前后都空着，靠眼睛摆不准。所以调试台拿折叠当校准基准时，头颈改成摆正（0°）。

校准时膝的目标按官方 1.57 rad 算，实际摆到的是接触点 89.59°，零点因此差约 0.36°（4 步），可以忽略。

## 对「缩着当标定基准」意味着什么

1. **顶住关节的都是脚和踝**，不是关节自己的限位。所以每个关节停在哪跟其它关节的角度有关：同样是「膝折到底」，髋 0° 时停在 70.7°，髋 90° 时停在 89.6°。
2. **踝在缩着时没被定住**，还有约 20° 的空间，拿缩着校不了踝。髋 yaw / roll、头本来就不受约束。
3. 真要用缩着校髋和膝，得把**摆法写死**（先把髋摆到多少度、踝往哪边推、再折膝），角度用同一套摆法算出来的值。
4. **这些是 XL330 原版的几何**。飞特版改过 8 个跟舵盘配合的件，接触角会变：要么把飞特版装配体按零位导出每个 link 的 STL 再跑一遍，要么在 SolidWorks 里按同样的摆法量。
5. 更稳的路是**标定夹具**：打印几个卡在大腿-小腿-脚之间的夹板，把关节卡在确定的角度（比如零位的伸直、脚板垂直），比「缩到底」好定义，左右也一致。

调试台（`tools/servo-web`，0.13.0 起）可以在 3D 里叠加官方姿势，逐关节列出「实际 − 官方」差多少度，用来看现在的零点偏了多少；0.15.0 起还能叠加「校准用折叠」（腿官方折叠、头颈摆正），就是校准时要摆的样子。

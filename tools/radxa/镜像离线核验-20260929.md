# 20260929 公开候选镜像离线核验

本次针对公开镜像首登失败与缺少 DHCP 的问题做核实。没有连接实机或读取个人 WiFi 镜像，也没有运行镜像内的 ARM 程序。候选版单独发布为 Pre-release，旧版文件保留。

## 首登根因

对 20260920 公开压缩镜像校验 SHA256，结果与 Release 一致：

```text
4de8a355d3d9180e465af486c409e9b3e4ac82c0e241dc73d4fc0f0db7a67579
```

从 GPT 读取根分区起始扇区 32768，以 `loop,ro,noload,offset=16777216` 挂载；只输出密码候选是否匹配，不打印 `/etc/shadow` 内容。

| 检查 | 结果 |
|---|---|
| `/etc/passwd` 中有 duck | 否 |
| root 密码匹配 `1234` | 是 |
| root 密码匹配 `duck1234` | 否 |
| `/etc/systemd/network/25-wlan0.network` | 缺失 |

原镜像 `/root/.not_logged_in_yet` 中的 `PRESET_ROOT_PASSWORD`、`PRESET_USER_NAME` 和 `PRESET_USER_PASSWORD` 只是向导输入。`/etc/profile.d/armbian-check-first-login.sh` 第 10–11 行在 root 登录后调用 `/usr/lib/armbian/armbian-firstlogin`；后者第 670 行读取预设，第 823 行设置 root 密码，`add_user` 内第 589 行创建普通用户、第 602 行设置密码，第 626 行删除首登标记。因此首次应使用 `root / 1234`，向导完成后才应用 duck 与新 root 密码；不能把预设当作首次认证凭据。

## 新候选产物

仅从上述公开镜像复制，离线改动：

1. 增加 `/etc/systemd/network/25-wlan0.network`，匹配 `wlan0`、`DHCP=ipv4`。
2. 更新 `/root/先连WiFi.txt`，明确首次 root 登录、向导、修改密码及联网；修复命令块中 heredoc 结束标记的缩进，提取命令后 `bash -n` 无错误和警告。
3. 移除原包的 3 组 SSH 主机密钥及公钥，清零相关内容和空闲空间。`/etc/machine-id` 为空，原系统已有启用的 `sshd-keygen.service`，`ConditionFirstBoot=yes`、`Before=ssh.service`、`ExecStart=ssh-keygen -A`；实际首次启动生成仍需烧卡验证。

全量比较两份只读挂载文件树的文件 SHA256、权限、属主及符号链接：只有上述 8 个文件路径不同。前 16 MiB 的引导区域逐字节一致。根分区 `e2fsck -f -n` 完成五个阶段，退出码 0。完整旧主机私钥内容在新裸镜像扫描中均未发现。

隐私核查覆盖 WiFi 认证文件、NetworkManager 连接、`/etc/environment`、authorized_keys、root/home 的 shell 历史及用户目录；原包无个人 WiFi/代理/用户凭据，新版未引入。保留的默认公开密码需首次使用时更换。核验报告见 [`image-verification-20260929.json`](image-verification-20260929.json)。

新产物仍是基础系统，没有加入网页调试台、机器人运行时、舵机设置、IMU 或策略。当前制卡脚本也已同步首登提示与 SSH 主机密钥处理；此次候选产物是对原公开镜像离线修补，并非重新运行整个制卡脚本构建。

## 尚未完成

尚未对这份新产物烧卡启动、验证新 SSH 主机密钥生成或实际 WiFi 连接。9 月 28 日个人 DHCP 修复镜像的联网实测不能代替本次候选文件的实机验收。摄像头、舵机控制、IMU 和步态也不在此离线检查范围。

# HAT 舵机偶发超时：头部接入对照与电路核对

日期以调试电脑为准。主板日志时钟不作为现场绝对时间依据。

## 已确认的现场接法

用户确认：可调电源**同一对正负输出端子**分成两路，一路直接供 HAT，另一路经飞特调试板给舵机供电；调试板 USB 未接电脑。HAT 到 33 号（左右歪头 / head_roll）目前只接 DATA。嘴部 ID 29 按用户要求不参与测试。

两路电源负线已提供共同参考地，不能称为“完全未共地”。但信号回流绕经电源负线与调试板，局部地偏移、回路面积及共同阻抗仍待对照。调试板 USB 未插，不等于其 DATA 电路必然断开或高阻；调试板型号、内部供电及 DATA 是否接通尚待核实。

## 软件误判与实测

重启后网页服务原为 inactive，确认串口无占用后，独立测试仅发送 PING / READ / SYNC_READ。没有发写参数、开扭矩或运动指令。随后恢复网页服务；仍未发送运动指令。

| 头部接入测试 | 结果 |
|---|---|
| 逐颗读取，各 20 次 | 33 号 19/20，其余 13 颗各 20/20 |
| 旧程序同步读取 200 轮，10Hz | 应用报告 43 次舵机读取失败；底层 6 次解析超时、37 个完整且校验正确的回包因与顺序预期 ID 不符被拒绝 |
| 原始回包按实际 ID 保存，正常顺序 200 轮 | 31 号缺 1 次，其余各 200/200 |
| 原始回包按实际 ID 保存，反向顺序 200 轮 | 33 号缺 3 次，其余各 200/200 |
| 修复后网页 0.15.3，200 帧，约 20 秒 | 14 颗各 200/200，窗口内无超时、校验错误或 ID 错误 |

“缺应答”仅指测试窗口内没取得该 ID 的有效回包，不等于已经证明物理线缆丢帧。改变读取顺序不会改变物理接线。

此前脚部接入的逐颗测试中，23 号为 18/20，其余各 20/20。但两次测试的时间、姿态、超时设置等并非完全一致，不能由小样本认定“接哪一侧、哪一侧必坏”或定量宣称头部接入更可靠。

独立 agent 用协议字节流复现：只省略 23 的一包，旧同步读取实现却报告 23 及后续 10 颗一起失败。原因是依次调用 `_read_status(expected_id)`，实际收到后面的有效包时按 ID 不符丢弃。0.15.3 改为按应答包自身 ID 归档，只对实际缺失者保留 None；不靠重试掩盖漏读，单颗读取仍严格检查 ID。遇到接收超时即结束该组，避免逐颗重复等待。

验证：新增协议回归测试先失败、修复后通过；相关 38 项测试及模拟自检通过；4 个实际异常事务的字节流回放均只报告真正缺失的 ID。独立复核通过。现有模拟测试有未关闭临时读取文件的 ResourceWarning，不影响本轮测试结果。实现仍限制为最多读取请求数量的帧，未实现任意噪声、重复包或非请求 ID 的完整恢复。

## 原理图、PCB 与规格书交叉核对

依据官方 HAT 原理图第 4/6 页、PCB 实际焊盘网络、生产 BOM，以及 HD-1910-C001 规格书 2026-09-07 A/0：

- J13/J14 两个三针口完全并联，共用一套 TTL 收发电路：pin1 GND、pin2 +BATT、pin3 DATA。没有按左右肢体分开的独立驱动。
- U7 为 SN74LVC1G126，U6 为 SN74LVC1G125，均由 3.3V 供电；Q1 为 MMBT3906，R27 10k、R28 20k 参与自动方向控制。
- 稳态下，TX 低使 Q1 导通、DIR 高、U7 使能并驱动低；TX 高时 DIR 被拉低，U7 输出高阻，总线由 R32 10k 及外接设备可能存在的上拉恢复高电平。切换瞬态和 Q1 延迟未实测；不能仅由图纸断言停止位被截断。
- DATA 路径为收发节点 → R33 150Ω → D4 钳位节点 → TH1 → J13.3/J14.3。TH1 的 BOM 型号为 Murata PRG18BB101MB1RB，标称 100Ω thermistor；实际阻值随条件变化，不能当作恒定电阻。**TH1 不在 +BATT 供电路径上**，旧文档的相反说法已更正。
- HD-1910 规格书列出工作电压 4–8.4V、默认波特率 1Mbps（每位约 1µs）、信号高电平 2–5V、低电平 0–0.45V。标称 3.3V 高电平匹配，不能据此保证带线束时的端点波形合格。
- 原理图的 `3A max` 旁注位于四针 J11，不能把它或 TH1 当成三针舵机供电已有恒流/熔断保护的证据。

独立 agent 再次解析 PCB 引脚网络并核对原图，确认上述拓扑。尚未量到边沿、振铃、地偏移或供电瞬态，**不能判定 HAT 芯片损坏、上拉阻值不合适、某颗舵机坏或需要磁环**。

## 下一项：一次只改变一个条件

后续进展见[3000 轮保持姿势状态回读摘要](50Hz保持姿势读状态-20260928.md)：调试台已更新至 0.15.4，目标 50 Hz，约 64 秒窗口内 14 颗无缺应答、实际约 46.87 Hz。以下是当时拟定的单变量排查方案，不表示每项至今都未进行；该窗口也未独立证明某一种接线调整是修复原因。

1. 正常关机并切断电源，在保持现有可靠供电正负线的前提下，补一根短 GND，随 DATA 同路径走，从 HAT GND 接至舵机 GND。只增加这条局部参考/回流路径，再复测相同 ID、1Mbps、10Hz、200 轮及较长窗口。新增细地线不能替代舵机大电流供电负线。
2. 若仍漏读，再单独隔离飞特调试板的 DATA，仅保留它已确认的供电与地；HAT 作为唯一通信接口，复测同样统计。即使 USB 没插，调试板仍可能通过收发器、上拉或保护结构改变总线负载，但目前没有证据证明正在争用。
3. 若仍存在，使用短的已知良好线缆作对照，或在断电重接后用飞特转接器单独连接同一组舵机，比较转接器与 HAT。切换控制端时断开另一端 DATA，避免把两种拓扑混成一组结果。
4. 有示波器时，依次测 HAT 连接器侧 DATA 对当地 GND、33 号侧 DATA 对当地 GND，并观察两端地偏移、舵机 VCC、TX 与 DIR 切换。重点看低电平能否落到规格范围内、高电平是否及时越过 2V、上升时间、振铃以及请求结束/应答开始。读回的 7.4–7.5V 不能排除很短的电源跌落。

HAT 与飞特舵机规格书的接口针号标法不同，应按 **DATA / VCC / GND 功能与实际接头方向**核对，不能直接照搬针号。

磁环只适合作为发现高频共模干扰后的对照措施，不能替代地参考，也不能修复软件错配、驱动争用、慢上升沿或供电压降。若后续测试磁环，优先评估整束线一起穿过夹扣磁环；不要未经测量就只在 DATA 上增加磁性串联阻抗。暂不建议改 R32、短接 TH1 或增加终端电阻：这些都会改变电流、边沿或保护条件。

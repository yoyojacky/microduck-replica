# 2026-10-11：用自己的运行器跑 kissqy 的 walk 模型

**一句话**：kissqy 仓库自带的 HD1910 行走模型，放在咱们这台鸭子上**能迈腿**，前提是放在地上、不用手托机身。当晚几次中途停下、全身卸力，原因都在咱们自己的运行器和硬件条件（保护阈值、供电余量、主板过热降频），不在他的模型。把节奏、供电、方向、舵机参数逐项排除后，仍然没有走出连续步态，所以**决定改用他的 Rust 运行程序**，IMU 继续用现成模块接主板 I²C，见第 9 节。

这份文档写给人看，也写给 AI 看：每条结论都写了「为什么」，数字都能在记录文件里查到。

---

## 1. 为什么不直接装他的整套

kissqy 的部署包（R17 升级包，robotd v1.0.146）是**叠在官方 Microduck 0.15.1 系统上的升级**，并且只认一种硬件配置：

| 他的程序要求 | 咱们这台当时的状态 |
|---|---|
| 卡上先装官方 0.15.1，再装 R17 | 卡上是自己的 Armbian 镜像 + servo-web + Python 运行器，没有官方运行程序 |
| IMU 挂在**舵机总线**上，ID 200，读地址 0 起 5 字节必须是 `06 00 00 00 F2` | IMU 是 **BNO085，接主板 I²C**（`/dev/i2c-4`，地址 0x4B） |
| 读不到 IMU 就不给舵机上力（`Feetech torque-on requires a fresh converged IMU`） | — |
| 首次安装写入他样机的标定并标记已标定 | 每台装配不同，必须重标 |

他的代码里**没有 I²C IMU 的路径**，所以 BNO085 对他的程序等于没有 IMU。咱们自己的 imu_to_dxl 小板（方案 A）身份字节是 `0.2 / 0x4D44`，改成他要的值只需改 `protocol.h` 三个宏，但小板还没上过真总线。

**所以当晚的做法**：模型用他的，运行程序用咱们 10-04 跑 Luwu 的那个（`tools/servo-web/run_luwu_trial.py`），加了一个 `kissqy_walk` 配置。观测（61 维）、关节顺序、站姿 HOME 都和他的部署合同一致，逐项对过。

两套 IMU 的整体策略见 [飞特适配架构](../software/飞特适配架构.md)：A 总线小板、B BNO085 直连主板，配置二选一。

- 文件：`Microduck-kissqy/microduck-hd1910/firmware/policies/walk/policy.onnx`，SHA-256 `1cbf8730eadd75a5704332c9f3c10f60bfa9412135b907831c9dbd731ce1795f`
- 任务 `Mjlab-VelStand-Rough-Backlash-MicroDuck`（行走 + 零速站立 + 倒地恢复联合），9600 轮，官方 microduck_rl `8d0db749`
- 输入 61、输出 14，50 Hz；训练指令范围前进 ±0.4 m/s；训练 BAM 执行器 `kp_fw = 5`
- 他的包里 `deployment_verified: false`；README 有实机视频

## 3. 运行参数：每个是干什么的、为什么有两套

模型每 20 ms 输出 14 个数：每个关节**在站姿基础上再转多少弧度**。发给舵机前可以加几道处理：

| 参数 | 作用（白话） | 训练时 | kissqy 运行时 | 我们的开关 |
|---|---|---|---|---|
| 动作缩放 | 输出乘系数再发；0.9 = 动作打九折 | 1.0 | 0.9 | 默认 0.9；`--training-mapping` 用 1.0 |
| 目标滤波（头 0.5 / 腿 0.7） | 新目标只取 70%，30% 沿用上一帧；更顺、但慢半拍 | 不加 | 加 | 默认加；`--training-mapping` 不加 |
| 电压补偿 7.4/V | 电压高舵机更有劲，就按比例缩小动作；8.0 V 时约 ×0.93 | 不做 | 做 | 默认做；`--training-mapping` 不做 |
| 增益 P/D | 舵机「硬度」，写 SRAM 地址 50/51，结束恢复原值 32/40 | P5 | P5 / D20 | 默认 P5/D20；`--kp N` 改 P（5–16） |

**为什么有两套**：kissqy 的 R17 说明写明，0.9 / 0.5 / 0.7 是他**照搬官方鸭子运行程序的默认值**（官方是给 Dynamixel 舵机调的），这个模型训练时实际是 1 / 1 / 1。两套都值得试，以实机效果为准。

他的运行端（R17 robotd）每一帧做的事，我们照着实现：

```
目标 = HOME + 缩放 × 原始输出 × (7.4 / 舵机平均电压)
目标 = α × 目标 + (1−α) × 上一帧目标      # α：头 0.5、腿 0.7；第一帧不滤波
下一帧观测里的「上一帧动作」= 原始输出（不缩放、不滤波）
写舵机：地址 42 起 6 字节 [位置低, 位置高, 0, 0, 0, 0]，和他的写法逐字节相同
```

另外加了一道他没有的保险：目标限在训练时的关节范围内（如髋 roll ±22°），当晚一次都没触发。

## 5. 理解（为什么会这样）

1. **手托机身测不出行走策略。** 这个模型的输入里没有「节拍」，迈步要靠身体晃动、重心转移，再由 IMU 和关节反馈带出来。机身被托住，身体不晃，输出很快收敛到一个静止姿势。第 2–5 次都是这样；第 6 次一松手，0.4 s 内就开始交替。**测行走模型要放地上，手只虚护。**
2. **「一动就泄力」是咱们运行器的保护造成的。**
   - 低压保护线 6.6 V 是给台架小动作定的；走起来电流大，7.4 V 供电在舵机端掉到 6.5 V 就触发。
   - 原地保持后要核对位置偏差 ≤ 1°，但正在动或在 P5 下沉的鸭子做不到，于是走到全身卸力。
   - 已改：保持和恢复阶段不再因电压低而卸力；保持判定放宽到 5°。回站是否到位仍按 1° 判断。
3. **供电要留余量。** 调到约 8.0 V 后，第 7 次 10 s 全程最低 7.6 V。HD-1910 上限 8.4 V，kissqy 训练的供电范围是 7.4–8.0 V。
4. **加大增益会把电流拉上去。** P10 时电流读数翻了几倍，可调电源扛不住，电压塌到 5.4 V。P 不能随便往上加；要加先试 6–8。
5. **P5 下腿跟不上。** 手托时目标和实际一直差 6–7°；地上第 7 次前 3 s 有摆动、之后蹲住。这是目前最大的未解问题。可能的原因：P5 的力不足以克服负载、实物与 BAM 仿真里的舵机模型有差距、0.9/0.5/0.7 这套运行参数，或者 BNO085 与他的 LSM6DSV16X 在延迟、噪声上不同。还没有区分出来。

6. **主板过热降频，控制节奏被拖慢。** 当晚主板 CPU 84–87°C（降频门槛 75 / 85°C，115°C 关机），频率被锁在最低档 408 MHz（最高 1800）。主因是网页服务 `server.py` 常驻占满一个核（top 显示 100%），主板又装在机身里。后果：在地上跑时控制周期中位 25 ms（约 40 Hz）、读传感器最慢 20 ms，模型按 50 Hz 训练。停掉网页服务后周期回到 20.2 ms。刚开机那次死机可能也与过热有关。
7. **节奏对了，动作做足，可调电源又成了瓶颈。** 按训练原样（不缩放、不滤波）且周期准确时，2 秒左右电流读数相加到 26 A，电压一起掉到 4.6 V。用他的 0.9 / 0.5 / 0.7 则全程 7.6 V 以上。软起步只解决起步那一下。
8. **方向、舵机参数、节奏、供电都排除后仍不走。** 剩下的差异都在运行层：Python 运行器 vs 他的 Rust robotd、I²C 上异步读的 BNO085 vs 和舵机同一次总线读取的 LSM6DSV16X。用户决定直接用他的 Rust 程序，去掉「咱们的运行器写得对不对」这个变量。

### 5.1 排除掉的怀疑

- **关节方向**：站姿角度接近 0 的 8 个关节（左右髋转向、左右髋侧摆、左右膝、头转向、头侧摆），方向反了站姿看不出来。用新工具 `joint_direction_check.py` 逐个转 +8°，用户目视 8 个全部和 MJCF 轴向一致。其余关节站姿角度不为 0，站姿正确即说明方向正确。
- **舵机参数**（`servo_report.py` 只读体检，15/15 在线，报告存在 `software/training/artifacts/hd1910_bench_20261011/kissqy-walk/体检-20261011-130324.md`）：15 颗设置完全一致——固件 3.46、模式 4、EEPROM 与 SRAM 的 P/D/I 都是 32/40/0、最大扭矩和转矩限制 1000、不灵敏区 ±1、最小启动扭矩 12、加速度 0、运行速度 3000、角度限制全开 0–4095、电压保护 4.0–10.0 V。没有哪颗被限了力或限了速，所以「腿跟不上」不是某颗参数设错。
- 体检标红的两项不影响今晚的测试，但要处理：卸载条件只开了过热（19 = 4），过流、电压保护没开（21 号就是这样烧的）；偏移量很大是装舵盘时的齿位差，标定已经吸收了，不是故障。

## 6. 自己怎么跑

前提：电源约 8.0 V；网页「站」；鸭子放地上，手虚护。登录主板：

```sh
sudo python3 /home/duck/policy-trial/run_luwu_trial.py --profile kissqy_walk --execute --supported --vx 0.15 --seconds 10
```

| 加什么 | 作用 |
|---|---|
| `--vx 0.1` | 前进速度 0–0.15（Luwu 配置仍限 0.05） |
| `--seconds 10` | 时长，最多 10 |
| `--training-mapping` | 按训练原样：缩放 1.0、不滤波、不做电压补偿 |
| `--kp 8` | 临时 P，5–16；P10 已把可调电源拉垮 |
| 不加 `--execute --supported` | 只读，不写舵机 |
| `--inspect-model` | 只检查模型，不碰硬件 |

注意：电脑开着 Clash 的 TUN 模式时，`ssh` 和网页都连不上主板，见[踩坑记录](../踩坑记录.md#软件)。

# 2026-10-12 凌晨：第一台换成 kissqy 整套（官方 0.15.1 + R17 + I²C IMU）

**一句话**：第一台没重烧卡，远程在原卡上装好了官方 0.15.1 和 kissqy 的 R17，换上咱们加了「IMU 接主板 I²C」的 robotd，BNO085 在真机上读通，15 颗舵机 50 Hz 全应答。鸭子用他的程序 **HOME 站到官方站姿，模型接管后原地保持了 10 秒**，机身倾斜从 6.6° 收到 3.3°。网页摇杆没走起来，原因是主板过热、CPU 被压到 408 MHz，网页手柄那条 Python 通路来不及响应；用户关机降温，行走留到散热解决以后。

这份文档写给人看，也写给 AI 看：每一步写了为什么这么做，数字都来自当晚的日志。上一晚（用自己的 Python 运行器跑同一个模型）见 [10-11 上机实测](HD1910-20261011-kissqy-walk上机实测.md)。

---

## 1. 为什么换成他的整套

10-11 用自己写的 Python 运行器跑 kissqy 的模型，节奏、供电、方向、舵机参数都排除后仍然走不出连续步态，剩下的差别全在运行层。kissqy 在群里演示他的整套已经走得很流畅，所以定了：**机器人上不再装自己那套，直接用 kissqy 的整套，只补他缺的东西**。

他缺的就一样：他的程序只认挂在**舵机总线**上的 IMU 小板（ID 200），咱们这台用的是 **BNO085 模块接主板 I²C**（`/dev/i2c-4`，地址 0x4B）。这部分代码在本地分支 `hd1910-trunk-imu-i2c` 里写好了，经过两轮审查，这次是第一次上真机。

## 2. 卡上原来是什么、为什么没重烧

原计划换新卡重烧，远程看了以后发现没必要：

| 项目 | 实际情况 |
|---|---|
| 系统 | Armbian 26.2.1 trixie，64 GB 卡只用了 2.2 GB，读卡没有报错 |
| 官方运行程序 | 一个都没装（robotd、updaterd 都没有） |
| 多出来的 | `microduck-servo-web.service`（开机自启）和 `/home/duck` 下的 servo-web、Python 运行器、记录 |
| 启动配置 | 瑞莎 U-Boot + `extlinux.conf`，overlay 已有 `uart2-m0`（舵机串口）、`dwc3-peripheral`、`i2c4-m0`（IMU） |

`i2c4-m0` 是 9 月底为 BNO085 加的，重烧反而还要再加一遍。所以直接在这张卡上装。动手前先把 `/home/duck` 和 `/etc`、`/boot/extlinux` 打包备份到电脑（`home-duck.tar.gz` 91.6 MB，`etc-boot.tar.gz` 0.4 MB），出问题可以原样放回。

## 3. 安装过程（按顺序）

### 3.1 停掉 servo-web

`systemctl disable --now microduck-servo-web`。它占着舵机串口，和 robotd 只能有一个在用。服务文件还在，要用时 `systemctl start` 即可，只是不再开机自启。

### 3.2 官方 0.15.1：固定版本，用本地文件装

- **为什么要固定 0.15.1**：kissqy 的 R17 是在官方 `daemon-v0.15.1`（提交 `1fa8438`）上改的。官方当时已经出到 0.16.1（10-07），而官方 `install.sh` 只会装**最新版**。
- **怎么固定**：在电脑上用 `gh release download daemon-v0.15.1` 下好 6 个发布文件，传到主板；把 `install.sh` 复制成 `install-local.sh`，只改两处：发布标签写死为 `daemon-v0.15.1`，`updaterd install` 加 `--from <本地目录>`。签名校验照常做，装完还会比对启动用的 updaterd 和发布包里的是否同一个文件。具体改法：

  ```sh
  # 1. 把 updaterd install 那一行改成从本地目录装
  GITHUB_TOKEN="$TOKEN" "${tmp}/updaterd" install --from "${DUCK_LOCAL_RELEASE}" \
      --config "${CONFIG_DIR}/updater.toml" $force_flag
  # 2. 文件末尾 main "$@" 之前加上：发布标签写死、启动用的 updaterd 从本地拷
  resolve_bootstrap_asset() {
      RELEASE_TAG="daemon-v0.15.1"
      BOOTSTRAP_URL="${DUCK_LOCAL_RELEASE}/updaterd-bootstrap-aarch64"
  }
  fetch_asset() { cp "$1" "$2"; }
  ```

  运行：`sudo env DUCK_REF=daemon-v0.15.1 DUCK_LOCAL_RELEASE=<放发布文件的目录> sh install-local.sh`。
- **第一次失败**：安装前的准备步骤要从 GitHub 下 ONNX Runtime 1.28.0（跑模型的推理库，微软出的），主板直连 90 秒超时。给 root 的 curl 临时加电脑代理（`/root/.curlrc` 写 `proxy = "http://192.168.0.100:7890"`），8.1 MB 两秒下完；装完已删掉。
- **慢在哪**：准备步骤还会用 apt 装 GStreamer、相机库这些系统包，占了 8 分半钟。
- **结果**：updaterd、robotd、configd、btd、padd、mediad 都是 0.15.1 并在运行。robotd 报「舵机总线上没有机器人」，因为官方原版只认 Dynamixel 舵机，读不了飞特，这是预期的。
- **关掉自动升级**：`/etc/robot/updater.toml` 里的 `auto_apply` 从 `"mandatory"` 改成 `"off"`，免得哪天它自己把 0.15.1 升到 0.16，把 kissqy 依赖的底子换掉。

**故意没跑的两个官方脚本：**

- `setup-board.sh`：它的音频步骤会 apt 装 Armbian 的 vendor 内核包，并把 `/boot/Image`、`dtb`、`uInitrd` 指向新内核。这块板子要靠瑞莎的 U-Boot 才能启动（见 [踩坑记录 · 主板](../踩坑记录.md#主板--hat--摄像头)），远程换内核有开不了机的风险。这台的 HAT 上虽然有音频芯片，但要用它就得换 vendor 内核、编译驱动，走路又用不到声音，先不开；它要做的其他几件事（舵机串口 overlay、串口控制台让位）卡上已经做好了。
- `migrate-network.sh`：把网络从 netplan 切到 NetworkManager，只有蓝牙配网用得到。远程切网络万一 WiFi 断了就连不回来，先不切。

### 3.3 kissqy 原版 R17：先装原版，确认基线

不直接装改过的版本，先装他的原版 `Microduck-Robotd-FT6-R17.tar.gz`（从 `Microduck-Firmware-R17-v1.0.146-Public.zip` 解出，包内 `SHA256SUMS` 全部校验通过），这样出了问题能分清是他的还是咱们的。安装方法和他中控里「系统维护 → 升级」一样：解压后执行 `sudo bash Microduck-Robotd-FT6-R17/service.sh upgrade`。

1. **卡在音频设置**：`alsactl store aic3104` 退出码 19。系统里没有 aic3104 这张声卡：HAT 上的音频芯片要靠官方 `setup-board.sh` 的音频那一步（vendor 内核 + 驱动）才能启用，我们没跑，所以只有 HDMI 声卡；没装 HAT 的板子也是这样。他的安装脚本默认这张声卡一定在。已在分支里修好（提交 `790b45d`）：没有这张声卡就跳过音频设置，别的不动，并补了测试。
2. **装上以后卡在「Feetech ID 200 无应答」**：他的程序要先读到总线上的 IMU 小板才肯往下走。第一台没有这块小板，这正是要补的。
3. **他把自己样机的标定抄进了本机**：本机没有标定文件时，安装脚本把包里**他样机的零位**写成本机标定，标记为「已标定」，还显示「运动就绪」。他样机的零位从 1372 到 2176 不等，方向有正有负（比如头部 ID 33 零位是 1599）；咱们这台用 servo-web 校准过，零位全是 2048，方向全是 −1。照他的值上力，关节会转到错误的角度。

### 3.4 换成咱们的版本 + 配 IMU

**安装包**：在 WSL 里解开他的原版包，换掉 6 个文件后重算 `SHA256SUMS`，再打包（`Microduck-Robotd-FT6-R17-imu.tar.gz`，sha256 `6c4de6db…`）。换的是 robotd（`618028ac…`）、robotctl（`f1bfc8e4…`），以及 `calibration-config.py`、`rebuild-config.py`、`runtime.py`、`voice-setup.py`。其余文件、模型、ONNX Runtime 与原版逐字节相同。

**配置**：在 `/etc/robot/feetech-ft5/robotd.toml` 末尾加上下面这段，再用同样的 `service.sh upgrade` 装：

```toml
[trunk_imu]
source = "bno08x"
i2c_device = "/dev/i2c-4"
i2c_address = 0x4B
```

**结果**（调试模式，不上力）：

- `trunk IMU: BNO08x identified part=10003676 version=(2, 6, 6) build=193`：BNO085 在真机上读通，这是咱们写的读取代码第一次碰真芯片；
- 15 颗舵机全部应答，控制循环 49.99 Hz；
- 约 1.7% 的周期 IMU 数据「过期」（2878 帧里有 48 帧超过 50 ms）。都是单帧，官方控制循环遇到读失败会沿用上一帧，最多 3 帧（60 ms），按设计不影响走路。原因还没查，可能也跟降频有关。

**标定**：kissqy 算关节角的公式是 `角度 = (读数 − 零位) × 方向 × 2π/4096`，和 servo-web 完全一样。所以把 15 个关节都改成零位 2048、方向 −1，用他的 `calibration-config.py copy` 写入（他的样机文件备份在主板 `/home/duck/r17/`）。写完后按新标定换算各关节角度：左右对称，大部分关节在 HOME 附近，两膝弯 83° 左右，跟鸭子卸力塌坐的样子一致。

### 3.5 确认 IMU 安装方向

他的程序在 IMU 方向确认之前不让上力、不让 HOME，这一关是咱们写 I²C 支持时照他的规矩定的。确认分两步：机身竖直时离竖直不超过 5°；然后往前低头 15–30°，倾斜方向要朝向正前方。

- **手扶软鸭子做不到**：第一次读到离竖直 15.2°（往前低头约 13°、往左歪约 8°）。没上力的鸭子腿是软的，很难扶正扶稳。
- **改成先站起来再测**：在 servo-web 页面点「站姿」。这组角度和官方 HOME 一模一样（髋 ±26.2°、踝 ±26°、颈和头 20°，换算成舵机读数逐个对过）。鸭子自己站住以后，从 servo-web 读 BNO085 的加速度，按默认安装方向（`[0.5, 0.5, 0.5, 0.5]`，传感器 X 朝左、Y 朝上、Z 朝前）算：

| 姿态 | 离竖直 | 往前低头 | 左右 | 说明 |
|---|---:|---:|---:|---|
| HOME 自己站着 | 4.95° | 4.81° | 往右 1.15° | 46 帧，抖动 0.41°，加速度模长 1.017 g |
| 用户把整只鸭子往前倾 | 21.07° | 20.94° | 往右 2.22° | 相对站立变化 16.2°，方向偏正前方 3.9° |

两项都满足他的标准（站立 ≤5°；前倾 ≥12°，方向在正前方 20° 以内），说明模块按默认方向装得是对的。**因为当时 robotd 没在运行，这次是手动把 `[imu_mounts.bno08x] quat = [0.5,0.5,0.5,0.5], verified = true` 写进标定文件的，没有走 robotd 的 `verify-imu` 命令。** 判断标准和 verify-imu 一样，但这一步是绕过程序完成的，所以记在这里。以后要让 verify-imu 支持「在 HOME 站姿下确认」（见第 6 节）。

### 3.6 切运动模式、HOME、保持

1. `service.sh enable`：切到运动模式（他的脚本会把标定标成可运动，并把 robotd 改成运动模式启动）。robotd 起来了，但他的就绪检查没过，因为它要求启动时舵机是卸力的，而舵机还保持着 servo-web 站姿时上的力。**运动模式启动不会卸力**（调试模式启动会）。
2. `service.sh init` 发不出 HOME：这个子命令要独占 robotd 的锁，robotd 正在运行时只会报 `another robotd owns this socket`。他的中控是通过 IPC 套接字（`/run/robotd.sock`，每行一条 JSON-RPC）发 `robot.init` 的，改用同样的方式就行。
3. **HOME 被拒**：第一次是上力回读超时；之后 4 次都是 `ID 20: temporary P/D readback mismatch; torque-on refused`。原因：他的程序如果发现舵机**已经上着力**，就当作是自己之前上的，只核对 P/D 是不是 P5/D20，不会重写。可那是 servo-web 上的力，P/D 还是 32/40，核对当然不通过。
4. **先卸力再 HOME**：用户扶着鸭子，发 `robot.relax`，1.5 秒后发 `robot.init`。日志显示写入 P5/D20 并回读确认、上力，2 秒转到 HOME（`at the home pose`）。
5. **保持 10 秒**：机身 6.6° 时发 `robot.enable on=true`，模型接管，零速度原地站。机身倾斜降到 3.2–3.6° 并一直稳着，关节离 HOME 最多 6.2°（模型自己在调姿势），没有报错。10 秒后发 `on=false`，回到 HOME 站姿。

### 3.7 中控和网页摇杆

- 中控用分支里的源码启动（`microduck-hd1910/firmware/console/`，`py -3 console.py --dashboard --feetech --open`，浏览器打开 `http://127.0.0.1:8090`），SSH 填 `duck@192.168.0.102`。这份带了 IMU 面板的改动，跟主板上的程序配套。电脑开着 Clash TUN，系统自带的 ssh 照样连得上。
- 连上后各项都对：50.0 Hz 稳定、关节 15/15、已标定 15/15、运动模式、扭矩 ON、IMU 在线且安装已确认、电压 7.60 V。
- **按 Start 没反应**：网页手柄在主板上的路径是「中控 → webpad（Python，用到才启动）→ 虚拟 Xbox 手柄 → padd → robotd」。webpad 要等 padd 确认接上虚拟手柄才发按键，最多等 0.6 秒；而 CPU 在 408 MHz 时 webpad 光启动就要 1.7 秒。等不到确认，这次按键就作废，虚拟手柄被撤掉，padd 随后去打开时设备已经没了（`Failed to open "/dev/input/event4"`）。robotd 一直没收到启用请求。kissqy 的主板跑在 1.8 GHz，不会碰到这个时间差。

## 4. 主板过热（当晚最大的问题）

| 时刻 | CPU 温度 | 频率 | 当时在跑 |
|---|---:|---:|---|
| 装完官方 + R17 | 89–90°C | 408 MHz | mediad 的 `gst-plugin-scanner` 占满一个核（99.5%），robotd 35% |
| 停掉 mediad、tofd 2 分钟后 | 85°C | 408 MHz | robotd |
| 中控连上、鸭子站着 | 86.9°C | 408 MHz | robotd、中控通道 |
| 查网页摇杆时 | 92.5°C | 408 MHz | 同上 |

- **为什么 mediad 这么吃 CPU**：没接摄像头，相机服务 mediad 启动就崩溃、不停重启，每次重启都要跑一遍 GStreamer 插件扫描。测距服务 tofd 没装传感器，也在反复重启。两个都 `systemctl disable --now` 了，以后接摄像头或 ToF 再打开。群里网友也说过，关掉用不到的服务温度会降下来。
- **关掉以后还是热**：主板装在机身里，没有散热片也没有风，robotd 一直在跑，温度又慢慢回到 92°C。408 MHz 是最低一档，所有东西都变慢：上力回读超时、网页手柄来不及响应，IMU 偶尔断档可能也跟它有关。
- **舵机**：从站立到 HOME 一直出力约一个小时，最高舵机温度从 40°C 升到 63°C。

用户当晚关机降温。散热要在下一次上机前解决。用户的思路：最简单的是在头壳或机身上开几个孔，能散掉一部分；真要散得下来，关键是**风道**，要有进风口、有出风口，风扇不一定非得贴在主板上。以后要把相机、ToF 等功能都打开，发热会更多，到时候再一起升级散热。

## 5. 别人照着做（IMU 用 BNO085 模块，HAT 音频没启用或没装 HAT）

1. 卡上有能启动的 Armbian（这块 V1.12 板要用瑞莎 U-Boot，见[不打 HAT](不打HAT.md)），`/dev/ttyS2`（舵机）和 `/dev/i2c-4`（IMU）都在。
2. 停掉占用串口的东西（比如 servo-web）。
3. 用本地文件装官方 `daemon-v0.15.1`（第 3.2 节），ONNX Runtime 下不动就给 root 的 curl 临时挂代理；`auto_apply` 改成 `"off"`。不跑 `setup-board.sh` 的音频部分和 `migrate-network.sh`。
4. `systemctl disable --now mediad tofd`（没有摄像头和 ToF 时）。
5. 在 `/etc/robot/feetech-ft5/robotd.toml` 加 `[trunk_imu]`，装带 I²C IMU 支持的 R17 包（`service.sh upgrade`）。
6. **马上换掉标定**：安装会把 kissqy 样机的零位当成本机标定。按自己的零位和方向写 `hd1910-calibration.toml`，算一遍关节角度，跟实物对得上再往下走。
7. 让鸭子站到 HOME（可以用 servo-web 的站姿），确认 IMU 方向：站立离竖直 ≤5°，前倾 15–30° 后变化方向朝前。
8. `service.sh enable` 切到运动模式。如果舵机还上着别的程序给的力，先 `robot.relax` 再 `robot.init`（HOME），HOME 时机身要在竖直 10° 以内。
9. 中控连上后按 Start 启用策略（保持），再用摇杆走。**主板别过热**，过热时网页摇杆会失灵。

## 6. 还没解决 / 下一步

1. **散热**：先解决（开孔，再做进出风的风道），然后测网页摇杆和行走。温度降下来后，看 CPU 能不能保持在 1 GHz 以上。
2. **网页摇杆**：散热解决后复测；还不行就考虑让 webpad 常驻，或者改用实体手柄（GameSir Nova 2 Lite），实体手柄不走这条 Python 通路。
3. **IMU 1.7% 过期帧**：查 BNO085 读取线程，看是降频造成的还是读取方式本身的问题。
4. **verify-imu 要能在站着时做**：现在调试模式一启动就卸力，鸭子站着就没法确认方向。要么让 verify-imu 在运动模式的 HOME 保持下也能用，要么调试模式加一个「保持上力」的选项。这次是手动写入的（第 3.5 节）。
5. **`service.sh init/enable-policy` 在 robotd 运行时用不了**（跟他的中控走的路径不一样），要跟 kissqy 确认这是不是有意的。
6. **行走**：还没走。
7. 第二台等第一台跑通再装。分支要不要发到咱们仓库、要不要给 kissqy 提 PR，等用户决定。

## 7. 主板现在的状态（下次开机）

- robotd 是 R17 + I²C IMU 版，开机按**运动模式**启动，舵机卸力；标定是咱们的（2048 / −1），BNO085 安装方向已确认，`motion_enabled = true`。
- servo-web、mediad、tofd 都不开机自启；官方自动升级已关。

## 8. 以后怎么接 IMU 模块、怎么散热（思路，还没上机验证）

### 8.1 IMU 模块别再飞线：HAT 上现成的口

第一台的 BNO085 现在是从主板 40 针的 1/6/27/28 脚飞线接的（I2C4，`/dev/i2c-4`）。HAT 上其实有现成的 4 针口（JST-SH 1.0 mm，顺序 1 GND、2 3V3、3 SDA、4 SCL，跟 Qwiic 一样）。下表按官方 KiCad 工程（`hardware-official/elec_RPI_Robot_HAT`，`4478fdf`）和咱们打板用的 C1 版 BOM 核对过：

| 接口 | 接到主板 40 针 | 能不能当 I²C 用 |
|---|---|---|
| J5 | 3 / 5（I2C3） | 能，硬件 I²C。官方原意接 ToF（0x29）。同一条线上还有板载芯片：音频 aic3104（0x18）都有；C1 版（咱们手上这块）还有 BMI088（0x19 / 0x68），D1 版换成 LSM6DSV16X（0x6A）。BNO085（0x4A/0x4B）两版都不冲突；外接 LSM6DSV16X 在 D1 上要用 0x6B。要启用官方的 `i2c3-pihat` overlay，代价是 USB-C 不再协商 PD（见踩坑记录），robotd 里的 `i2c_device` 改成实际的 `/dev/i2c-N`。 |
| J6 | 默认经 R18/R19（0Ω）接 7 / 29；板上预留了 R16/R17（0Ω，默认不贴）可以改接 27 / 28 | 能。27/28 就是现在 BNO085 用的 I2C4。**拆掉 R18、R19，在 R16、R17 贴 0Ω（或者短接）**，J6 就直接变成 `/dev/i2c-4`，板上已经有 10k 上拉（R20/R21），软件一个字都不用改。网上说的「短接几个器件就能当 I²C 用」，说的应该就是这个口。 |
| J7 | 24 / 21 | 这是 SPI 的脚，带 10k 上拉，不是硬件 I²C。只能用 `i2c-gpio` overlay 模拟 I²C，CPU 开销和时序都不如前两个。 |
| J8 | 19 / 23 | 同 J7。 |

第一台 J5 实际空着（ToF 没接）。建议：

- **改 J6**（拆 2 颗、短接 2 颗 0402 电阻）：软件不用动，IMU 插上就是现在的 `/dev/i2c-4`，以后 J5 还能留给 ToF。
- **不想动烙铁就用 J5**：要改 overlay，接受 USB-C 不协商 PD；以后 ToF 和 IMU 可以串在同一条线上。

两种接法都只是按原理图推出来的，第一次改要先用 `i2cdetect -y 4`（或对应的总线号）确认能看到 0x4B，再启动 robotd。

C1、D1 两版逐个焊盘的对照（板载芯片地址、J6 跳线电阻、IMU 模块要装在躯干上）见 [kissqy 镜像 R1 分析 §9](HD1910-20261012-kissqy镜像R1分析.md#9-hat-上接-imu-模块c1旧版咱们手上这块和-d1官方最新版对照)。

### 8.2 散热：开孔 + 风道，风扇不一定要放在主板上

HAT 和主板叠在一起，板上已经塞满了，放不下风扇。用户的思路：

1. **先开孔**：头壳顶上、机身下部各开几个孔，热空气往上走，下面进风、上面出风，不加风扇也能带走一部分热。
2. **再做风道**：风扇放在风道里任何方便的位置（比如头壳出风口），只要气流能从主板旁边经过、能进能出就行，不用贴在板子上。
3. 主芯片上贴一块小散热片，配合风道效果更好。
4. 风扇供电用 5 V（40 针的 2、4 脚和 GND），别用 HAT 上 JST 口的 3V3：那路 3.3 V 来自主板，电流有限，而且跟传感器共用，风扇的噪声会串进去。

改之前和改之后，都在同样的状态下（robotd 运行、鸭子站着）读 `/sys/class/thermal/thermal_zone0/temp` 和 `/sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq`，看温度能不能稳在 80°C 以下、频率能不能离开 408 MHz。

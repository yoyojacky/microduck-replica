# 2026-10-12：kissqy「一键系统镜像 R1」拆解，以及在它上面改出 V1.12 能开机的卡

**一句话**：kissqy 10-12 发布的整卡镜像做得很用心，账号、密钥、WiFi 这些隐私都处理干净了。但它是按他那套硬件做的：Armbian 原版引导、HAT + 音频 + 摄像头 + NPU、IMU 是总线上的小板。咱们的 V1.12 板很可能开不了机，IMU 模块他的程序也不认。开机这一层可以在他的镜像上直接改，脚本已经写好并离线验证过；IMU 模块支持要等他公开 V164 源码，才能把咱们的补丁移植过去。

这份文档写给人看，也写给 AI 看：结论都写了依据，怎么查的也写了，别人可以照着复查。

---

## 1. 怎么查的

- 从他的发布页下载 `microduck-zero3w-0.15.1-R1.img.xz`（767 MB）。sha256 `75da978b…a7bce5`，跟他公布的一致。
- 在 WSL 里解压（3.16 GB），**只读**挂载根分区，从头翻一遍：引导区、启动配置、预装的服务和程序、标定、账号，再按特征扫一遍令牌和私钥。镜像里的程序一个都没运行，只读文本、看文件属性，二进制只用 `strings` 看。
- V164 的安装脚本和更新说明拷出来，跟 v146 的发布包逐个文件对比。

## 3. 做得好的（照着学）

- **没有残留任何隐私**：没有 GitHub 令牌、私钥、他家的 WiFi 密码、命令历史；日志清空。
- **账号默认锁着**：root 和 radxa 都没有密码，必须在首次配网时自己设。
- **每张卡的 SSH 主机密钥不同**：镜像里没有，首次开机才生成；machine-id 也清空了。
- **自动升级关掉**：免得官方更新把他的底子换掉。咱们 10-12 凌晨装第一台时也是这么做的。

## 4. 跟咱们硬件对不上的地方

| 问题 | 影响谁 | 依据 |
|---|---|---|
| **V1.12 板可能开不了机** | 咱们第一台这批 V1.12（AIC8800）；群友说 2026-09 这批 V1.12J 还要换设备树 | 引导是 Armbian 主线 U-Boot 2025.10 + DDR v1.21。第一台 9 月就卡在这套组合上，换成瑞莎引导才起来（见[踩坑记录 · 软件](../踩坑记录.md#软件)）。他的板子能开，说明他那一批没问题 |
| **只认总线 IMU 小板** | 用 BNO085 / LSM6DSV16X 模块的人 | 固件里只有读 ID 200 的代码，身份要求 `06 00 00 00 F2`（他的 FT6 固件），没有 I²C IMU；启动配置也没开 I2C4（27/28 脚） |
| **预装他样机的标定，IMU 标成「已确认」** | 所有人 | `hd1910-calibration.toml` 的零位是他那只鸭的（2281、2176……），方向全 −1，`imu_mount_verified = true`。好在 `motion_enabled = false`，不会一上电就动 |
| **相机、测距服务默认开** | 没装摄像头或 ToF 的人 | 没有设备时 mediad、tofd 会不停崩溃重启，主板会热到降频，见[上机记录 §4](HD1910-20261012-kissqy整套上机.md) |
| **默认全套 HAT 配置** | 不打 HAT 的人 | 音频芯片、I2C3 的 overlay 都开着；不打 HAT 不影响开机，但这些功能用不了 |
| **robotd 没有 I²C 设备权限** | 以后在他的镜像上加 IMU 模块支持 | robotd 的 systemd 配置只放行了舵机串口和声卡，没有 `char-i2c` |

## 5. V164 比 v146 改了什么（跟咱们有关的）

从镜像里拷出的更新说明（R150～R157-Fix6）：

- **网页手柄换了做法**（R157）：网页输入改成通过一条常驻 SSH 连接直接发给 robotd，**不再虚拟 Xbox 手柄，也没有 webpad 服务了**。10-12 凌晨咱们「按 Start 没反应」就是卡在 webpad 那条路上（降频时它来不及启动），新版应该没有这个问题了。
- **启动流程**（R150、R153、R157）：先确认 15 颗舵机都卸力，再等 IMU 就绪；初始化最多重试 5 次，不再失败一次就退出；没就绪时拒绝 HOME 和策略。
- **撤掉了模型导入**（R154）：中控不能再导入模型。以后做动作社区要问他原因，或者走官方的 `robotctl policy load`。
- 安装脚本里，跟咱们 IMU 补丁有关的文件：`calibration-config.py` 没变，`rebuild-config.py` 改了 13 行，`runtime.py` 改了 189 行，`voice-setup.py` 改了 23 行；`uart-service.py`、`webpad.py` 被删掉。补丁的打包部分能移植，robotd 部分要等源码。

**他仓库里的源码还是 v146**，他在 README 里写明了「旧版仓库源码暂未同步升级」。

## 6. 在他的镜像上改：分三层

### 6.1 开机这一层：已经做好

脚本 [`tools/radxa/kissqy-r1-v112.sh`](../tools/radxa/kissqy-r1-v112.sh)，在 WSL 里运行：

```bash
sudo bash kissqy-r1-v112.sh microduck-zero3w-0.15.1-R1.img.xz [--no-camera] [--no-tof] [--overlay i2c4-m0]
```

它只改这几处，其余原样保留（他的固件、模型、首次配网、账号锁定、SSH 密钥首启生成都不动）：

1. 扇区 64、16384 写入瑞莎 `u-boot-rk2410 2017.09-64` 的引导（跟咱们[做卡脚本](../tools/radxa/README.md)用的同一个包，sha256 锁死）；
2. 新增 `/boot/extlinux/extlinux.conf`。瑞莎引导只认这个文件，不认 `boot.scr`。overlay、设备树、内核参数都从镜像自己的 `armbianEnv.txt` 搬过来，他的 HAT 音频、摄像头、NPU 照旧生效；
3. `--overlay NAME`：额外加 overlay，比如 `i2c4-m0`（IMU 模块接 40 针 27/28 脚时用）；
4. `--no-camera`、`--no-tof`：没装摄像头、ToF 时，不让 mediad、tofd 开机自启；
5. 在 `/etc/microduck-v112-image.txt` 写明这张卡是怎么改出来的。

**离线验证结果**（按 `--no-tof --overlay i2c4-m0` 做了一张，`microduck-zero3w-0.15.1-R1-V112.img`，sha256 `652dd54e…4c5bcc`）：

- 引导区跟瑞莎官方包逐字节一致，内存初始化固件 v1.25；
- 扇区 0～63（分区表）没动，镜像大小不变；
- 根分区跟原版逐个文件比对，只多了 `extlinux.conf` 和说明文件，改了 `armbianEnv.txt`，少了 tofd 的自启链接，别的一个字节都没变；
- extlinux 里引用的内核、initrd、设备树和 6 个 overlay 文件都在。

**还没上机**：要拿一张空卡烧它，在第一台上试开机和热点配网。第一台现在那张卡别动。

## 9. HAT 上接 IMU 模块：C1（旧版，咱们手上这块）和 D1（官方最新版）对照

用 IMU 模块（BNO085、LSM6DSV16X）、又不想从主板 40 针飞线时，可以插 HAT 上现成的口。下面两版的数据来源：

- **C1**：咱们打板用的生产文件 `官方HAT-production/`。Gerber 里带了每个焊盘的网络名（X2 属性 `TO.P` / `TO.N`），再对照 BOM。
- **D1**：官方 KiCad 工程 `hardware-official/elec_RPI_Robot_HAT`（提交 `4478fdf`）的 `kicad_pcb`。

都是按生产文件和原理图推出来的，**还没上机接过**。

### 9.1 四个 4 针口，两版定义相同

J5～J8 都是 JST-SH 1.0 mm 4 针（BM04B-SRSS-TB），脚序：**1 GND、2 3V3、3 SDA、4 SCL**。这跟 Qwiic / STEMMA QT 一样，带 Qwiic 口的模块用标准线直接插。

| 接口 | 接到主板 40 针 | 是不是硬件 I²C | 说明 |
|---|---|---|---|
| J5 | 3 / 5（IO_02 / IO_03） | 是，Zero 3W 的 I2C3 | 要启用官方的 `i2c3-pihat` overlay，代价是 USB-C 不再协商 PD；kissqy 镜像 R1 已经开着。板上 10k 上拉 R12/R13 |
| J6 | 默认 7 / 29；可改接 27 / 28 | 改接后是 I2C4 | 见 9.3 |
| J7 | 24 / 21 | 不是（SPI 的脚） | 带 10k 上拉，只能用 `i2c-gpio` 模拟 I²C，不推荐 |
| J8 | 19 / 23 | 不是（SPI 的脚） | 同 J7 |

### 9.2 J5 这条线上已经挂了什么：两版不一样

I²C 是总线，地址不冲突就能挂好几个。所以接之前要先看板子上已经有哪些芯片占了哪些地址：

| 芯片 | C1（咱们手上这块） | D1（官方最新版） |
|---|---|---|
| 音频 aic3104（U2） | 0x18 | 0x18 |
| 板载 IMU | BMI088（U11）：加速度计 SDO1 经 R14（0Ω）接 3V3 → **0x19**；陀螺 SDO2 经 R15（0Ω）接地 → **0x68** | LSM6DSV16X（U12）：SDO/SA0 经 R30（0Ω，已贴）接地 → **0x6A** |
| ToF（官方原意，咱们没接） | 0x29 | 0x29 |

外接模块的地址：

- **BNO085**（0x4A / 0x4B）：两版都不冲突。
- **LSM6DSV16X**（0x6A / 0x6B）：C1 上两个都能用；**D1 上必须用 0x6B**，0x6A 被板载那颗占了。模块上的 SA0 要接高电平，robotd 里也要显式写 `i2c_address = 0x6B`。

### 9.3 J6 改成 I2C4：软件一个字都不用改

两版 J6 的接法一样：

- pin 3：经 **R18（0Ω，默认贴）**接 40 针 7 脚，经 **R17（0Ω，默认不贴）**接 27 脚；
- pin 4：经 **R19（0Ω，默认贴）**接 29 脚，经 **R16（0Ω，默认不贴）**接 28 脚；
- 10k 上拉 R20/R21 都在。

C1 的 BOM 里写的就是 R16/R17 `DNP-0R`（不贴）、R18/R19 `0R`。**拆掉 R18、R19，在 R16、R17 贴 0Ω（或短接）**，J6 就接到了 27/28，也就是 I2C4，也就是 `/dev/i2c-4`，跟第一台现在 BNO085 飞线用的是同一条线。咱们 robotd 的默认配置就是它，插上就能用。网上说的「短接几个器件就能当 I²C 用」，指的应该就是这个口。

### 9.4 板载 IMU 为什么不能直接用

C1 的 BMI088、D1 的 LSM6DSV16X 都焊在 HAT 上，官方把它当「头部 IMU」（`robotd.toml` 的 `[head_imu]` 注释写的是 head module 上的 BMI088；0.16.1 读 beta 板 LSM6DSV16X 的提交也叫 head IMU）。按这个注释，再加上用户说要在头壳上开孔散热，**推断 HAT 跟主板装在头里**。头相对身体会转，而策略要的是**躯干**的姿态，所以板载这颗不能当躯干 IMU。

外接模块要固定在躯干上，线从头里的 HAT 经过脖子下来。要用软线，长度留够关节转动的余量，两头都做好应力释放。第一台现在从 40 针飞线下来的 BNO085 也是这么走的。

### 9.5 软件怎么配

插 J5 时，`/etc/robot/feetech-ft5/robotd.toml`：

```toml
[trunk_imu]
source = "bno08x"            # LSM6DSV16X 写 "lsm6dsv16x"，并且必须写 i2c_address
i2c_device = "/dev/i2c-3"    # 以实际编号为准
i2c_address = 0x4B
```

- 先用 `i2cdetect -y 3` 确认能看到模块的地址（0x4A/0x4B 或 0x6A/0x6B），以及板载芯片的地址，再启动 robotd。
- 第一台现在那张卡**没开 i2c3 overlay**，要在 `/boot/extlinux/extlinux.conf` 的 `fdtoverlays` 那行加 `rk3568-i2c3-pihat.dtbo`。这块板走的是瑞莎引导，**改 `armbianEnv.txt` 不生效**。另外这个 dtbo 是官方 `setup-board.sh` 编出来的，第一台没跑过它，要先确认 `/boot/dtb/rockchip/overlay/` 下有这个文件。
- 改 J6 就不用动这些：还是 `/dev/i2c-4`。

### 9.6 选哪个口

- **咱们这套优先改 J6**：软件不动，J5 留给以后的 ToF。
- **不想动烙铁就插 J5**：改 overlay，接受 USB-C 不协商 PD，地址按 9.2 避开。
- 第一次接，都先 `i2cdetect` 看到地址再说。

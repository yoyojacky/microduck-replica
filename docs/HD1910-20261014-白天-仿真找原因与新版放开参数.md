# 2026-10-14 白天 · 仿真对照找蹭地原因、鞋底、新版放开 P / D / 转矩（未上机）

**机器**：同 [10-13 夜](HD1910-20261013-夜-掉电-舵机D与蹭地.md)。白天鸭子不在线，**本页全是电脑上的分析和代码准备，没有新的上机数据**。用到的真机数据，都是 10-13 下午到 10-14 凌晨旧卡录的那几段。
**前情**：10-13 夜发现两只脚离地都只有仿真的一半（3～6 mm 对 11～12 mm），撑地膝盖伸不直；D 改成 0 以后，左脚迈步时脚尖朝下。

**一句话结论**（第 1～5 条是仿真里的发现，真机都还没验证）：
1. **仿真要先对齐条件才能跟真机比**。早上那几组仿真用的是：动作缩放 1.0、不滤波、整鸭 737 g，跟真机不一样。真机旧卡上，联合模型实际的动作缩放约 0.83（0.9 × 电压补偿），腿滤波 0.7、头滤波 0.5；kissqy 训练用的 HD-1910 模型是 820 g（我们这只没称过，先按它估）。对齐以后（陆吾参数、P4、820 g），仿真里撑地膝盖 −3.4° / −3.5°，已经接近真机的 −4.5° / −2.6°；离地 7.4 / 7.3 mm，真机是 4.8 / 5.8 mm。**仿真里看，「撑地膝盖伸不直」大部分能用缩放、滤波、重量这几个条件解释**；但那组仿真在颤（见下一条），电压也没对齐。
2. **对齐以后，仿真里出现了真机没有的高频颤**：颤占 96%、步频 4.1 Hz，真机 D0 只有 6%、3.0 Hz。仿真里还有几种情况也会这样：脚底太滑（摩擦 0.3）、飞特参数配 P3、飞特参数在 737 g 上加重 200 g 以上（陆吾参数在缩放 1.0 时加到 300 g 并不颤）。仿真和真机在这一点上对不上，原因没查，所以仿真只能用来找方向，不能直接下结论。
3. **动作缩放是现成能调的一项**：同样带着滤波，缩放从 0.83 提到 1.0，仿真里离地从 11.1 / 10.4 mm 升到 14.0 / 13.0 mm，撑地膝盖从 −1.3° / +0.1° 升到 +3.2° / +6.1°。但真机做不到这么多：联合缩放从 R17 的 0.9 改成 1.0（V164 默认就是 1.0），还要乘电压补偿（8.0 V 时约 0.925），实际只从 0.83 升到约 0.925，加 11%；仿真里是加 20%。按线性估，真机的提升大约只有仿真的一半（仿真没跑 0.925 这一组）。值得在真机上试，同时盯着供电。
4. **两项影响不大**：设不设 70% 的输出上限，仿真结果几乎一样（陆吾参数削掉的只是峰值，飞特参数一次都没碰到），真机上没验证；速度也不是差距的原因，真机推摇杆时中位 0.21～0.25 m/s，仿真对照用的是 0.2。
5. **鞋底**：我们的鞋底是 TPU 95A，偏硬；kissqy 说他的 90A 用两天就变硬打滑。仿真里地面太滑会变成小碎步加颤，但真机 D0 并不颤，所以不能说问题就出在鞋底。换软鞋底很便宜，值得试。
6. **站 HOME 时两只脚左右方向不共面**：差别全部来自两个髋横滚没跟到 HOME 目标，每次站定都不一样，方向都是「腿往外劈」，像是被体重压的（推测；依据是实测关节角加仿真几何）。零位偏差用这个方法看不出来，没排除。
7. **kissqy 新版（V164）的 P / D / 转矩限制和头腿滤波，我们在本地放开了**：代码、测试、审核都做完了，**还没上机**，不公开。

## 1. 仿真怎么做的，跟真机差在哪

- **模型**：kissqy 的行走模型，就是真机上跑的那个 `walk/policy.onnx`，一点不改；
- **仿真**：官方训练工程 0.15.1 的场景 `scene_backlash.xml`（带齿隙），舵机用 BAM（舵机的物理模型）。我们在本地改了训练工程里的推理脚本，加了几个开关：换舵机参数文件、限制舵机输出上限（仿真里对应转矩限制）、给躯干加重、改脚底和地面的摩擦、头腿滤波（跟 robotd 一样：每拍「新目标 = α × 模型目标 + (1 − α) × 上一拍目标」）；动作缩放是脚本原来就有的参数。**这个脚本只在本地，没放进仓库**，命令是这样的（方括号里是按需加的）：

  ```
  HEADLESS=1 SIM_SECONDS=24 BAM_JSON=<舵机参数 json> MAX_PWM=0.7 \
    [EXTRA_MASS_G=83] [FRICTION=0.3] [HEAD_LOWPASS=0.5 LEGS_LOWPASS=0.7] \
    python infer_policy_kq_cmp.py --walking walk/policy.onnx --new-cmd-obs \
      --lin-vel-x 0.2 --kp-fw 4 --action-scale 0.83 \
      --scene src/mjlab_microduck/robot/microduck/scene_backlash.xml --save-csv 输出.csv
  ```
- **怎么比**：仿真录的数据转成跟真机录像一样的格式，用同一套 [`tools/gait-analysis/`](../tools/gait-analysis/) 脚本分析；
- **真机对照**：10-14 凌晨 P4 / D0 / 681、IMU 已补的那组（[10-13 夜 §5.2](HD1910-20261013-夜-掉电-舵机D与蹭地.md#52-几组参数对比每组走-842-秒)）。注意它只走了 12 秒（报告脚本建议 15 秒以上才可靠），转矩限制是 681，不是 700。

**条件对照**（早上没对齐，是下午审核时发现的）：

| 条件 | 真机（旧卡 P4 那组） | kissqy 训练 | 早上的仿真 | 下午补跑（对齐） |
|---|---|---|---|---|
| 动作缩放 | 0.9 × 电压补偿（7.4 / 电压，8.0 V 时约 0.925）≈ 0.83 | 1.0 | 1.0 | 0.83 |
| 头 / 腿滤波 | 0.5 / 0.7 | 不滤波 | 不滤波 | 0.5 / 0.7 |
| 整鸭重量 | 没称 | 820 g（模型包里各部件质量合计） | 737 g（官方 0.15.1 的模型） | 820 g（83 g 全加在躯干上，跟 kissqy 的分布不同，见 §4） |
| 舵机 P / D | P4 / D0 | P5 / 模型里没有 D | P4 / 没有 D | P4 / 没有 D |
| 转矩上限 | 681 | 不限 | 70% | 70% |
| 舵机电压 | 约 8.0 V | 没核对 | 7.4 V | 7.4 V |

## 2. 对齐条件以后：撑地膝盖接近了，但仿真多出了颤

陆吾参数（kissqy 训练用的那份）、P4、输出上限 70%、0.2 m/s。舵机电压这一项没对齐（仿真 7.4 V，真机约 8.0 V）：

| 仿真条件 | 撑地膝盖 左 / 右（+ 是伸直） | 离地间隙 左 / 右 | 机身横滚晃动 | 其中 >4 Hz（颤） | 步频 |
|---|---|---|---|---|---|
| 早上：缩放 1.0、不滤波、737 g | +3.5° / +6.5° | 12.7 / 11.9 mm | 36.5°/s | 8% | 3.14 Hz |
| 只把缩放改成 0.83 | −0.6° / +1.5° | 9.6 / 8.9 mm | 33.5°/s | 6% | 3.68 Hz |
| 只加滤波（缩放 1.0） | +3.2° / +6.1° | 14.0 / 13.0 mm | 39.0°/s | 7% | 2.80 Hz |
| 缩放 0.83 + 滤波（= 真机设置） | −1.3° / +0.1° | 11.1 / 10.4 mm | 37.4°/s | 9% | 3.31 Hz |
| 再加到 820 g | **−3.4° / −3.5°** | **7.4 / 7.3 mm** | 37.2°/s | **96%** | **4.10 Hz** |
| **真机** P4 / D0 / 681 | **−4.5° / −2.6°** | **4.8 / 5.8 mm** | 43.7°/s | 6% | 3.01 Hz |

读法：
- **缩放 0.83 是撑地膝盖伸不直的大头**：动作整体小了 17%，模型要「伸直」的那一下也小了。只改这一项，膝盖就从 +3.5° / +6.5° 掉到 −0.6° / +1.5°；
- **滤波反而让脚抬得更高**：步频从 3.1 降到 2.8 Hz，步子变慢变大。所以两样一起加，离地只比早上低 1.5～1.6 mm；
- **再按 kissqy 训练模型的 820 g 加重**，撑地膝盖 −3.4° / −3.5°，跟真机的 −4.5° / −2.6° 差不多了；离地 7.4 / 7.3 mm，还比真机高 2 mm 左右。注意这 83 g 我们全加在躯干上，kissqy 的模型是分在腿上、头上的（§4）；
- **但这时仿真变成 4.1 Hz 的碎步，颤占 96%**，真机 D0 不是这样。仿真里还有几种情况也会变成这种碎步加颤：脚底太滑（§6）、飞特参数配 P3（§3）、飞特参数加重 200 g 以上（§4）。真机为什么不这样，没查，可能跟仿真里的舵机模型、关节摩擦有关。这一条没弄清以前，仿真的数字只能当方向看。

**能拿去用的**：缩放 0.83 → 1.0 这一项，仿真里效果很大（带滤波时：离地 11.1 / 10.4 → 14.0 / 13.0 mm，撑地膝盖 −1.3° / +0.1° → +3.2° / +6.1°）。真机上能做的是把联合缩放从 0.9 改成 1.0（V164 里这个联合模型默认就是 1.0，R17 是 0.9），但还要乘电压补偿：8.0 V 时实际只从 0.83 升到约 0.925，加 11%，仿真里是加 20%。按线性估，真机的提升大约只有仿真的一半（仿真没跑 0.925 这一组）。10-13 夜 [§7.5](HD1910-20261013-夜-掉电-舵机D与蹭地.md#75-下一步一次只改一样) 第 3 条本来就打算试它。缩放大了电流也大，要先把供电弄好（10-13 夜 §2）。

## 3. 两份舵机参数：陆吾的和飞特官方的

两份参数：陆吾公开的 1910 M6（kissqy 训练用的），飞特官方的 HD-1910（[参数来源](HD-1910-M6参数来源.md)）。飞特那份我们是**近似接进来的**：官方给的是专门的 HD1910 控制模型，我们仿真里套的还是陆吾那份用的 STS3215 控制模型，把官方 m6 的参数换算过去（增益比 0.982、速度上限 100）。

早上（缩放 1.0、不滤波、737 g），P4、输出上限 70%：

| | 撑地膝盖 左 / 右 | 离地间隙 左 / 右 | 机身横滚晃动 | 颤 | 步频 |
|---|---|---|---|---|---|
| 陆吾参数 | +3.5° / +6.5° | 12.7 / 11.9 mm | 36.5°/s | 8% | 3.14 Hz |
| 飞特参数 | +0.6° / +3.3° | 10.9 / 9.9 mm | 36.8°/s | 7% | 3.35 Hz |

下午对齐条件（缩放 0.83、滤波）以后：

| | 撑地膝盖 左 / 右 | 离地间隙 左 / 右 | 颤 | 步频 |
|---|---|---|---|---|
| 陆吾参数 | −1.3° / +0.1° | 11.1 / 10.4 mm | 9% | 3.31 Hz |
| 飞特参数 | −1.0° / −1.6° | 12.3 / 10.6 mm | 10% | 3.01 Hz |
| 陆吾参数，820 g | −3.4° / −3.5° | 7.4 / 7.3 mm | 96% | 4.10 Hz |
| 飞特参数，820 g | −4.9° / −6.0° | 7.4 / 6.4 mm | 36% | 1.00 Hz（步态乱了） |

- 早上看起来飞特参数更像真机；条件对齐以后，两份差不多，飞特那份加到 820 g 时步态乱了。**两份参数谁更像我们的舵机，仿真里分不出来**。要定，得在真机上做单关节阶跃响应，跟两份参数各比一次；
- **转矩上限**：P5、737 g 时，设不设 70% 的输出上限，结果几乎一样（陆吾参数：不限 13.4 / 12.1 mm，限 70% 13.5 / 12.4 mm；飞特参数两组数据完全相同，说明限幅一次都没触发）。陆吾参数下膝盖偶尔要出到 70% 以上（10-13 夜 §5.2 最后一段），削掉的只是这点峰值。这只说明仿真在这个条件下影响不大，**真机上能不能排除，没验证**；
- **P3 时仿真反而不如真机稳**：仿真 P3（缩放 1.0），陆吾参数晃 54.7°/s、离地 9.7 / 11.0 mm；飞特参数颤 97%、4.27 Hz 碎步。真机 P3 / D0 只晃 30～36°/s、颤 4～8%。这跟 §2 最后一条是同一类对不上。

## 4. 重量：仿真用的模型比 kissqy 训练时轻 83 g

- 官方 0.15.1 的仿真模型，整鸭 **737.2 g**，其中躯干 199.2 g；
- kissqy 模型包的 `deployment-contract.json` 里，各部件质量加起来是 **820.0 g**（`model.total_mass_kg = 0.82`）。也就是说，他是在一个 820 g 的 HD-1910 版模型上训练的。跟官方模型逐个部件比，多出来的 83 g 是这么分的：躯干 +14.8 g；两条腿共 +40 g（每侧 `upper_leg` +10、`yaw2roll`（右侧那个叫 `bearing_roll`）+5、`leg` +5）；头颈共 +28 g（`jaw_soft` +13、`neck` +10、`yaw_roll_motion` +5）；
- 我们这只**没称过**。

早上在 737 g 的基础上给躯干加重（缩放 1.0、不滤波，P4、输出上限 70%）。+100 g 大约就是 kissqy 的训练重量：

| 躯干加重 | 陆吾：离地 左 / 右，撑地膝盖，颤 | 飞特：离地 左 / 右，撑地膝盖，颤 |
|---|---|---|
| 不加（737 g） | 12.7 / 11.9 mm，+3.5° / +6.5°，8% | 10.9 / 9.9 mm，+0.6° / +3.3°，7% |
| +100 g | 11.4 / 11.1 mm，+3.2° / +4.5°，6% | 8.9 / 8.6 mm，−0.1° / +0.9°，9% |
| +200 g | 9.3 / 9.5 mm，+1.8° / +1.7°，5% | 7.0 / 6.8 mm，−2.0° / −0.8°，**88%** |
| +300 g | 8.5 / 7.9 mm，+0.2° / −0.5°，5% | 6.3 / 6.4 mm，−3.0° / −2.1°，**98%** |

- 越重，撑地膝盖越伸不直、脚抬得越低，方向跟真机一样；飞特参数加 200 g 以上就变成碎步加颤；
- 仿真里重量全加在躯干上，kissqy 的模型多出来的重量大半在腿上、头上（见上），效果不一样；我们这只的重量分布更不知道；
- **称一下**：厨房秤，电源线提起来别压到秤。拿实测重量跟 820 g 比：重得越多，这一条的嫌疑越大。大家用的都是 HD-1910，称一只就有参考价值。

## 5. 速度：不是差距的原因

| | 前进速度 |
|---|---|
| 真机推摇杆时（中位 / 最大） | P3 / D0：0.23 / 0.30；P4：0.25 / 0.30；P5 / D0：0.21 / 0.28；10-13 下午 P5 / D20：0.13 / 0.30 m/s |
| 手柄推满 | 0.3 m/s（padd 的 `--max-linear` 默认值） |
| 模型训练范围 | 前后 ±0.4 m/s，左右 ±0.3 m/s，转向 ±1.0 rad/s |

仿真（陆吾参数、P4、输出上限 70%，缩放 1.0、不滤波）：

| 给的速度 | 离地间隙 左 / 右 | 撑地膝盖 左 / 右 | 步频 |
|---|---|---|---|
| 0.2 m/s | 12.7 / 11.9 mm | +3.5° / +6.5° | 3.14 Hz |
| 0.3 m/s | 15.0 / 13.9 mm | +5.5° / +8.6° | 2.93 Hz |
| 0.4 m/s | 16.7 / 16.3 mm | +6.0° / +10.0° | 2.72 Hz |

- 真机推摇杆时中位 0.21～0.25 m/s，已经不低于仿真对照用的 0.2，所以**跟仿真的差距不是速度造成的**。速度最低的 10-13 下午那组（0.13），离地也不比别的组低（6.9 / 6.5 mm；那组是 D20，而且跟 P3 / D0、P5 / D0 那几组一样是 IMU 补偿前录的，带约 2 mm 偏差）；
- 仿真里速度越大，步子越大、脚抬得越高：推满到 0.3，大约多抬 2 mm；
- 比较几组参数时，摇杆每次都推满，让速度一样。要到 0.4 得改 padd 的 `--max-linear`，先不动。

## 6. 脚底摩擦和鞋底

### 6.1 仿真

kissqy 这个模型训练时，每个仿真环境的脚底摩擦系数在 0.7～1.3 之间随机取（训练配置 `foot_friction`；脚的接触优先级设得比地面高，所以生效的就是脚这一侧的摩擦），没见过更滑的地面。仿真里同一个模型、其他条件不变（缩放 1.0、不滤波），只改摩擦（两只脚和地面一起改）：

| 摩擦系数 | 离地间隙 左 / 右 | 机身横滚晃动 | 其中 >4 Hz（颤） | 步频 | 撑地膝盖 左 / 右 |
|---|---|---|---|---|---|
| 不改（模型原值） | 12.7 / 11.9 mm | 36.5°/s | 8% | 3.14 Hz | +3.5° / +6.5° |
| 0.5 | 12.6 / 12.2 mm | 37.6°/s | 10% | 3.05 Hz | +3.0° / +6.4° |
| 0.3 | 7.6 / 7.1 mm | 43.7°/s | **99%** | **4.48 Hz** | −0.1° / +0.6° |
| 0.2 | 走不动（步频算出来只有 0.5 Hz，机身前倾到 39°） | | | | |
| 0.3，速度加到 0.4 | 9.0 / 9.1 mm | 41.4°/s | 52% | 3.97 Hz | +3.6° / +4.8° |

- 0.5 几乎没影响；降到 0.3，就变成 4.5 Hz 碎步、几乎全是高频颤、脚只抬 7 mm；
- 真机只有 10-13 下午 P5 / D20 那组颤得多（51%），在「颤」这一点上像；但那组步频是 2.89 Hz，不是仿真这种 4.5 Hz 的碎步。而且 **D 改成 0 以后，同一张桌面上真机就不颤了**（用户确认 D20 和 D0 两组是在同一张桌面上走的，所以「D 改成 0，颤从 51% 降到 4～8%」成立）。如果桌面真滑到 0.3，按仿真 D0 时也该颤。所以仿真**解释不了**真机 D0 的样子，「脚底太滑」只是一个没排除的嫌疑；
- 用户觉得鸭子在鼠标垫上比在桌面上走得好，这是手感，没有数据。

### 6.2 我们的鞋底和要换的材料

- 10-14 跟伙伴确认：我们的鞋底是 **TPU 95A**。10-12 夜「要装 TPU 鞋底」那条要改成：TPU 也分软硬，95A 偏硬；
- kissqy（群里说的）：他买的 90A 用两天就变硬、开始打滑，又换了 85A。群里也有人说「还不如直接买个硅胶」；
- 用户在群里说我们的碎步感觉像摩擦，kissqy 回：「这个问题我还没解决，但是可以通过 home 增益来解决，因为加了滤波就会软」；
- 我们和伙伴商量的办法：**85A TPU**，或者 **PLA 脚板 + 硅胶 / 橡胶防滑片**。伙伴视频里试的是一种波纹橡胶防滑贴，软、能弯，看着 1～2 mm 厚；
- 我们的建议（经验，没测）：
  - 薄、平：1～2 mm，两只脚一样厚，贴平、贴满，边不能翘，脚的尺寸跟仿真模型差不多；
  - 防滑片前端（脚尖）修个斜角或倒圆，别超出脚板边：现在迈步时脚只抬 3～6 mm，脚尖一道硬边最容易勾地；
  - 别用厚海绵、EVA（太软会陷，机身高度和晃动都会变）；别用带砂粒的防滑胶带（太抓，会刮地板）。

### 6.3 怎么测摩擦（还没测）

- **斜板法**：摩擦系数 = tan（开始滑时的角度）。35° ≈ 0.70（训练的最低值），30° ≈ 0.58，25° ≈ 0.47，20° ≈ 0.36，15° ≈ 0.27；
- **不能拿整只鸭子站在斜板上测**：重心高、脚短，会先翻倒再滑（审核时粗算，脸朝坡下放时十一二度就会翻，侧着放约 25°，没实测）。要做一个矮样块：同材料打一块 3×3 cm 的方片，粘在小盒子底下，上面压 100～300 g；
- 板子用鸭子平时走的那种面，慢慢抬，样块刚开始滑就停，用手机水平仪读角度，测 3 次取中间值；
- 用户觉得不好测，先没测。换鞋底前后，在同一张桌面上用同样参数各走一组，比颤和离地，也能看出来。

## 7. 站 HOME 两只脚左右方向不共面：两个髋横滚往外劈，每次不一样

10-13 夜 [§6](HD1910-20261013-夜-掉电-舵机D与蹭地.md#6-imu-横滚零点往回补-114) 留了一个问题：按舵机读数，两只脚掌在左右方向不在同一个平面上。今天用新脚本 [`home_roll.py`](../tools/gait-analysis/home_roll.py) 把它拆到每个关节：

| 哪段（站 HOME / 停下保持） | 两脚横滚差（相对 HOME） | 左髋横滚 实际 − 目标 | 右髋横滚 实际 − 目标 | 躯干摆正时哪边低（仿真几何） |
|---|---|---|---|---|
| 10-13 下午 P5 / D20 | −0.86° | +0.5° | −0.3° | 两脚外侧低 1.9～2.0 mm |
| P5 / D0 / 850，3 段 | −9.76°、−5.02°、−4.93° | +4.7°、+3.0°、+2.9° | −5.1°、−1.9°、−2.0° | 第 1 段两脚内侧低 1.2～1.6 mm；后两段外侧低 0.1～0.9 mm |
| P3 / D0 / 681，5 段 | −3.72°、−3.81°、−3.81°、**−13.08°**、−1.30° | +1.4°、+1.6°、+1.5°、+6.9°、+0.2° | −2.3°、−2.2°、−2.3°、−6.0°、−1.1° | 多数外侧低 0.6～2.1 mm；−13° 那段两脚内侧低 2.2～2.9 mm |
| 10-14 凌晨，5 段 | −0.60°、−2.60°、−1.65°、−2.54°、−1.56° | +0.3°、+2.2°、+1.0°、+0.3°、+1.3° | −0.3°、−0.3°、−0.6°、−2.2°、−0.3° | 两脚外侧低 0.6～2.1 mm |

这些段都是「保持 HOME」的帧，有的是刚站起来，有的是走完停下（P3 那段 −13° 时陀螺还在晃）。10-13 夜 §6 那「6 次 0.4°～2.6°」用的是另一组样本、另一种算法（分别按左脚、右脚踩平算机身横滚），所以范围对不上。

**能确定的**：
- 两脚横滚差**全部来自左右两个髋横滚**：髋偏航最多偏 0.4°，其他关节不影响左右方向；
- 两个髋横滚每次都没跟到 HOME 目标，偏差方向**每次都是左 +、右 −**，大小每次不同（0.2°～6.9°）。

**零位那条看不出来**：脚本比的是「舵机读数 − HOME 目标」，读数和目标用的是同一个零点。所以零位偏了多少，这个方法根本看不见；10-13 夜 §6 猜的「髋横滚零位差 1～2°」，既没证实也没排除。能说的只是：每次都不一样的那部分，不是零位。

**为什么往这个方向偏**（推测，有几何依据）：仿真模型里，髋横滚轴离身体中线 17.5 mm，脚掌中心离中线 40.7 mm，地面托着脚的力落在轴外侧约 23 mm，产生的力矩正好让左髋往 +、右髋往 − 转，也就是腿往外劈，像是被体重压的。偏多少跟 P 的关系，数据里看不出来（P5 / D0 那几段反而比 P3 的多数段偏得多）。仿真里的策略站着时，髋横滚也有同方向的跟随误差（左 +1.6°、右 −1.8°），真机多数在 0.2°～2.3°，同一个量级；只有 P5 / D0 第 1 段和 P3 那段 −13° 明显超出。

**哪条边着地**：仿真模型在 HOME 姿势、躯干摆正时，两只脚掌本来就是**外侧边低约 2.3 mm**（脚宽 44 mm，每只约 3°，两只脚底之间差 5.97°，就是脚本开头自检行的那个数）。腿往外劈时外侧边抬起来，大约劈到 +2.9° / −2.9° 时脚就平了，劈得更多就变成内侧边低。仿真的脚是一个简化的碰撞盒，真鸭子的脚加上鞋底不完全一样，**哪边真的翘起来要看实物**：站 HOME 时从正前方、贴着桌面看两只脚掌，内侧边、外侧边哪边底下透光。

**更正**：10-14 上午我们口头说过「脚掌落在内侧边、外侧边翘起」，14 段里有 12 段正好说反了（只有上面那 2 段是内侧边低），以本节为准。那句话是凭直觉推的，没算过；后来写的临时脚本取「最低的 4 个角」当脚底，脚掌前后一倾就会取错，仓库里的 `home_roll.py` 改成按碰撞盒最薄的方向找底面。

## 8. 新版（V164）放开 P / D / 转矩限制和头腿滤波（本地，未上机）

### 8.1 为什么要做

先说叫法：kissqy 把 1.0.146 和 1.0.164 两个中控都叫 R17。本仓库说的「R17」，指旧卡上那套（中控 1.0.146、板上 R17）；「V164」指新的那套（中控 1.0.164、板上 control.40）。

- 10-13 夜发现：kissqy 新版（V164，新卡上跑的）上力时只写 P（模型合同里的 5），D 和转矩限制留在舵机出厂的 D=40、1000（[10-13 夜 §4.2](HD1910-20261013-夜-掉电-舵机D与蹭地.md#42-舵机的-p--d--转矩限制r17-能设v164-不能)）。D 对走路发颤影响很大（同一页 §5）；
- V164 配套的中控（1.0.164）「高级参数」页里，**根本没有 P / D / 转矩这三个框**，只有一个联合缩放滑条；头腿滤波只显示，不能改。有这三个框的是 R17 配套的旧中控（1.0.146）；
- 他 R17 里那套「参数文件 → 上力时写入 → 卸力时恢复」的代码，在 V164 里还留着，只是没接上（他在 v1.0.154 有意去掉的，没写原因）；
- 用户想用 kissqy 的新版（他在持续维护，以后的新模型也会给新版出），就在新版上把这几样放开。
- **补充（10-14 晚）**：kissqy 10-14 发布 V167 / control.43（中控 1.0.167），说明是「修复鸭身抖动」：每次 HOME 上力，把 15 颗舵机 RAM 里的 D 写成 0、转矩限制写成 1000，P 仍用模型里的 5；这两个值是固定的，中控里调不了；卸力时只恢复 P，D 留在 0，直到舵机断电。所以 D 这一项他已经解决了；可调版剩下的用处是 P、转矩限制、头腿滤波可调（比如我们用的 P3 / 700）。可调版还是在 V164 上做的，还没合到 V167（两边改的是同一段上力代码，要仔细合）。

### 8.2 做了什么

- **板子上的 robotd**：把 R17 的参数文件接回来。文件是 `/etc/robot/feetech-ft5/servo-test-parameters.json`，robotd **打开舵机串口之前**先读；文件坏了，robotd 停在「等待总线」并报错，不碰舵机；
- **安装包脚本**：`service.sh` 加三个命令：`servo-parameters P D 转矩限制`、`servo-parameters-clear`、`joint-filters 模型标识 头部滤波 腿部滤波`。顺序都是：校验 → 卸力，并**确认原值已经写回** → 停 robotd → 写文件 → 重启 → 回读核对。写失败、停不下来，都会把 robotd 重新拉起来。标定模式下只保存。确认卸力这一步只在 robotd 正处于运动模式的控制阶段时做；robotd 没响应、在等总线、在标定模式时，直接停；
- **电脑上的中控（1.0.164）**：「高级参数」页加两块，「舵机参数」（P、D、转矩限制，「应用」和「恢复默认」）和「联合模型滤波」（头、腿）。缩放沿用 kissqy 原来就有的滑条。滤波只改当前联合模型包里 `deployment-execution.json` 的头、腿两项，第一次改时把原件存成 `.orig`；
- **范围比寄存器允许的收得更紧**：P 1～32、D 0～64、转矩限制 200～1000，都必须是整数；滤波 0.10～1.00、两位小数；
- **保险**：P 大于 10 要确认两次（以前 P10 把可调电源拉垮过）；转矩限制低于 500 会提示可能站不住；中控连着我们的板子时，拦住「安装 / 升级固件」（§8.4）；
- **不设参数时，行为跟 V164 原版完全一样**。

### 8.3 舵机参数是怎么生效的：写 RAM，不写 EEPROM

- **设一次就一直有效**：参数存在板子上的文件里，断电、重启都还在，不用每次重设；
- 每次 HOME 上力：robotd 先读 15 颗舵机当前的转矩限制、P、D（48～51 号寄存器）记下来，再把文件里的值写进舵机 **RAM**，回读核对，对不上就不上力；
- 每次卸力：把记下的原值写回去，回读核对；
- 怎么确认生效：`robot.busStatus` → `native.hd1910.servo_parameters` 是 robotd 加载的值，`temporary_gains_applied: true` 表示已经写进去并回读核对过。`registers_before_arm` 是上力前读到的原值，正常应该是出厂的 D40 / 1000，不是设进去的值；
- **为什么不写 EEPROM**：舵机断电后，RAM 会从 EEPROM 重新载入（HD-1910 出厂是 P32 / D40 / I0、转矩限制 1000）。kissqy 的 R17、V164 也都这么做，V164 每次上力往 RAM 写 P=5。这样 EEPROM 不会被反复擦写，出了任何问题，舵机断一次电就回到出厂值。

### 8.4 要注意的两件事

1. **上着力时 robotd 被重启过，测试参数会留在舵机里**。原值只记在 robotd 的内存里，进程一重启就没了。V164（包括我们的可调版）和 R17 的过程不一样，结果一样：
   - **V164 / 可调版**：robotd 一启动就先把 15 颗舵机全部卸力，**鸭子会当场瘫下去**（扶好）。下次 HOME 时，它把舵机里残留的测试值当成「原值」记下来，卸力时写回去的还是测试值；
   - **R17**：启动时不卸力。新起来的 robotd 看到舵机已经上着力，只核对值跟文件一不一致：一致就接着用，不会再记一份原值；不一致就拒绝 HOME（跟[踩坑记录](../踩坑记录.md#策略训练与真机迁移)「用别的程序上了力再切到 kissqy，HOME 会被拒」是一回事）。之后卸力时没有原值可写回；
   - 继续用可调参数，没影响：每次 HOME 照样按文件写；
   - 点「恢复默认」、回到原版行为（只写 P，不碰 D 和转矩）以后，D 和转矩会停在刚才的测试值，不是出厂的 D40 / 1000。这时**给舵机断一次电**（或者按手柄十字键右「重启舵机」），RAM 重新从 EEPROM 载入；
   - 从中控正常改参数碰不到这种情况：脚本会先确认卸力、原值已经写回，才停 robotd。会碰到的是 robotd 崩溃、手动 `systemctl restart`、上着力装程序这类意外。
2. **装了自己改过的 robotd，别在中控里点「安装 / 升级固件」**。它会装回 kissqy 安装包里自带的 robotd，我们的 I²C IMU 补丁和可调版一起被冲掉；他的安装脚本还会删掉参数文件（有意的，用来清掉旧版的手动参数）。拦这个按钮的只有我们本地的中控，而且只拦可调版的板子；用 kissqy 原版中控连上去，或者旧卡（R17 加我们的 I²C IMU 补丁）用旧中控连上去，都没人拦。真要回原版，用 kissqy 原版的中控来装，装完舵机断一次电。

### 8.5 测试和审核（还没上机）

- Rust：`duck-control` 189 项全过，其中新加 3 项（包括 15 颗写入再恢复、写到一半出错仍能恢复）；`robotd` 的测试结果跟没改的 V164 完全一样（有 20 项原版也不过，是我们电脑环境的原因）；
- Python：安装包原有的 48 个测试文件，结果跟原版一致；新加 15 项全过；界面测试 1 套通过；
- 方案、代码各请独立审核（另开一个 AI 会话只读审查）审过一轮。审出 1 处必须修（参数文件坏了以后，中控的「恢复默认」是灰的、点不了），和几条建议，都改了；
- 界面用模拟数据截图看过，显示正常。

### 8.6 上机计划和撤回

- 新卡开机，鸭子趴着先不上力 → **只读**核对标定（已知新卡的 IMU 四元数还是 10-12 的值，没含 10-14 补的横滚 1.14°），差异给用户看、同意了再改 → 装可调版（原文件备份成 `*.bak-20261014-tunable`）→ 先不设参数起一次，确认跟原版一样 → 设 P3 / D0 / 700，HOME 后读寄存器确认写进去了，卸力后确认恢复了 → 走路出报告；
